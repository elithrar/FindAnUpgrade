## Settings grid and persistence contract

Reuse XPIsland's **620Ã—462** shell, 16px section margins, two 288px columns (x=16 and 316), 12px interior offsets (controls x=28 and 328), 260px full-width controls, 24px dropdown text box, 22px numeric edits, 28px checkbox rhythm, owned menu Font, native radio rows, and guarded refresh. Three stable pages keep the requested settings out of the search panel: **Appearance**, **Behavior**, **Search defaults**. Tabs use XPIsland's existing native-looking buttons and active underline. Pages construct once, refresh state on reopen, and close menus/focus on page change and hide.

- **Appearance:** font selection from Game tooltip (default), known native font choices and installed SharedMedia names; border selection None plus a small verified Blizzard set (Dialog, Tooltip, Thin/Slider only if the actual asset is appropriate); existing scale and tint strength; quest colors, dialog tint, reward details and preview layout. Keep current typography sizes and the 80â€“120% scale range unless the implementation needs a separately justified range. Border None removes only the chosen owned panel edge, not backgrounds, reward rarity borders or native controls. Settings remains discoverable and draggable without a border.
- **Behavior:** existing enable, reveal modifier, position, preview surfaces and minimap-launcher settings. Preserve their semantics and current defaults. Do not add extra operational modes.
- **Search defaults:** Hide unusable (true), Include dungeon quests (false), independent whole-number levels below (5) / above (3). The initial sidebar scope remains Same zone; the existing transient scope control is retained. The level fields describe offsets from current character level, not absolute cached levels. Keep both offsets available regardless of default scope so switching to level mode has the configured window.

Persist appearance and saved defaults in the model's versioned profile schema. Validate/clamp scale, border enum, font strings and numeric offsets through the same model path for migration and UI edits. Existing valid settings survive; missing new fields get the stated defaults. Unsupported future schemas remain read-only. Font lookup failure uses the current locale-compatible native tooltip/game fallback without erasing the saved preference, and late media registration refreshes owned text once.

Search state is a separate runtime object: typing, changing slot/sort/scope, editing absolute level bounds and checking temporary filters does not silently rewrite saved defaults. The locked session contract is explicit: on **every hidden-to-shown opening**, reapply saved Hide unusable / dungeon choices and the current-level-minus-below / plus-above window, and clear `manualRange`. Preserve the existing query, slot, scope and sort session values. Editing saved defaults while search is visible does not alter its current temporary filters; the saved values apply at its next opening. Reload reconstructs the runtime state with the normal current-zone scope. Global **Reset** resets saved appearance/behavior/defaults, while search defaults follow the same next-opening rule; it does not erase external addon state. This requires no extra main-panel control.

The agreed integration contracts are `Model.SearchDefaults(profile.searchDefaults)` returning `hideUnusable`, `includeDungeons`, `levelsBelow` and `levelsAbove`; `UI:Border(frame, defaultKind)` for owned dialog/tooltip surfaces; `UI:FontEntries()` for native/media font choices; and `Core:ChangeSearchDefault(key, value)` for persisted default edits.

Scale changes preserve the existing logical anchor relationship, then refit/clamp the complete sidebar, keep the drag handle reachable, and recompute measurement/scroll range. Font or border changes restyle existing objects; they do not rebuild the sidebar, rehydrate character data, or regenerate open menus on unrelated quest/item events. Font/menu changes made in Settings regenerate menu descriptions intentionally after closing obsolete menus.

## Implemented interpretation and focused evidence

The settled sidebar uses the shared native input-border slices described above; no textholder-padding estimate ships. Search clear is a 24px target with a 32px right text inset. Runtime bullet and multiplication-sign strings use exact UTF-8 Lua byte escapes, asserted in the focused tests. Reward captions and the multiple-location selector sit below their icon groups. Native `NumberFontNormalSmall` face, size and outline remain intact for item levels and quantities; the font preference applies to ordinary owned text, inputs and menus, with no global font mutation.

Appearance changes have a separate coalesced path over retained search results. Font, border, scale, viewport changes and resize completion reflow existing rows without a catalog query; an actual concurrent data invalidation retains its normal query. Geometry changes emitted by native `OnSizeChanged` cannot turn appearance work into data invalidation. Open native menus defer this reflow until release. The focused regression exercises these transitions with a native-style size callback, rather than relying on the broad mock's silent `SetSize`.

Focused execution after these changes passed 25 sidebar design cases, 16 search runtime cases, 22 search lifecycle cases and 57 search/model cases (120 total). Independent source/geometry review additionally exercised fractional-scale viewports and translated labels, and accepted the shared artwork and reward alignment. These establish source and offline behavior only; apparent native rendering and physical input still need client observation.
