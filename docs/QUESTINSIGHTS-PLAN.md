# QuestInsights: a restrained quest preview

Planning only, revised 14 October 2026 for Matt's interactive multi-quest stack clarification. No rename, feature implementation, game installation or release has been performed. This plan expands the reviewed QuestTint candidate into **QuestInsights** while preserving the XPIsland/ATCF framework and verified Forever interface **16001 / 1.60.1.70338**. The interaction below supersedes the earlier mouse-transparent panel and immediate dismissal on Shift release.

## Recommended first experience

Keep ordinary hover native. **Shift-hover opens a small vertical stack of condensed quest cards, one per identified quest.** Pressing Shift after entering a valid hover also opens it. Each card shows the title/status, compact guaranteed-item icons, a separate **Choose one** icon row, money and reputation where actually known. Hovering an item opens the game's native item tooltip, with native rarity colors and supported comparison behavior. Do not reproduce item stats in QuestInsights.

Opening latches the stack: **releasing Shift leaves it open** while the pointer stays over the source, crosses into the stack, or rests on a card or its item tooltip. A short guarded transit corridor prevents the NPC/marker's normal leave event from closing it on the way. **Escape or leaving that combined interaction area dismisses it.** The stack stays at its opening position; it does not chase the cursor or change NPCs while the user is inspecting rewards. One stack can be open at a time. Native clicks, tracking, reaction colors, item rarity colors and quest difficulty colors keep their existing meaning.

Use the native tooltip skin for unchanged quests, a subtle **green** background/border accent for modified quests, and **orange** for new quests. Add short textual **Modified in Forever** / **New in Forever** labels so color is not the only signal. Tint each quest card rather than all text. An NPC with a mixed quest list gets separately styled cards and a neutral outer container; it must not become wholly orange because one quest is new. Unknown IDs also retain normal appearance, with a small **Status not verified** line in their card.

The existing offer-dialogue tint remains a separate option. Recommend aligning its semantic colors with the same green/orange classifications while preserving native text, contrast settings, layout and buttons. Shift controls hover insights, not whether the native quest dialogue opens or whether a quest is accepted.

`/qi` and `/qi opts` open the same lazy, cached XPIsland-style options dialog: native controls, dark chrome, restrained gold headings, checked optional Expressway/SharedMedia fallback, measured labels and small-screen fitting. Recommended defaults: insights enabled, opening modifier Shift, items/money/reputation enabled, native-style status accents enabled, existing offer tint enabled, native item inspection on reward hover, no new minimap button and no automatic quest selection. Allow Alt/Ctrl/None as opening modifier alternatives, text-only status cues, tint strength, font size/scale and independent supported-surface toggles. All modifier alternatives use the same persistence/dismissal model; modifier release is not a close action. Static reputation estimates are off by default. A plain capability note explains a missing NPC/marker preview without exposing implementation details.

The first version uses native exact-ID rewards and an **optional read-only Forever QuestieDB association adapter**, following ATCF's existing provider boundary. It does not bundle a new quest/reward database. World-map support is the strongest first complete surface; broad NPC and native minimap coverage are bounded capability gates, not assumed promises.

## Reward data rules

1. **Match the context before reading anything.** The current offer's `GetRewardMoney`, item counts and item getters describe that open offer. Use them only when the expected offered ID and NPC/session match. A different hovered quest uses explicit-ID getters, never a hidden `SetSelectedQuest`/gossip selection to borrow native context.
2. **Separate general quest data, reward data and item metadata readiness.** ID-based item/money getters are used by the pinned map code. `HaveQuestRewardData` and reward preloading are separate from `C_QuestLog.RequestLoadQuestByID` / `QUEST_DATA_LOAD_RESULT`. A metadata success does not establish that every reward is loaded or that arbitrary unaccepted ordinary Forever quests are queryable. Verify those cases in the first spike. Do not reuse Blizzard's full reward renderer as the complete summary: its native item path deliberately chooses just one item.
3. **Enumerate guaranteed items and choices independently.** Retain exact item ID/link, quantity and native quality color; label mutually exclusive options **Choose one**, with the actual exposed choice count. Do not sum choices, assume the first option is best or treat class/spec-hidden variants as obtainable. Native-visible currency choices and guaranteed currencies remain distinct. Spell/unlock rewards should be acknowledged when exposed, without turning the preview into a second quest window.
4. **Show player-context money, not a guessed database formula.** Format copper as native gold/silver/copper. Required turn-in money is a cost, separate from the reward; optionally show **Cost** when known. Max-level XP conversion, level scaling and conditional bonuses require current-player results and rereads, not one immutable value per quest ID. XP may be an optional secondary field; it is not a sum of base and total XP.
5. **Reputation has a specific unresolved boundary.** Verified APIs return major-faction reward rows and reputation-related currencies. They do not yet establish a general query for every ordinary Classic faction payout before acceptance. A faction name, a `DoesQuestAwardReputationWithFaction` boolean, or an empty incomplete table is not an amount. Default to an explicit **Reputation: unavailable** where needed. If later enabled, provider reputation must read **Database base estimate**, include source provenance, preserve multiple factions and negative amounts, and never override a current authoritative value or promise final buff-adjusted/spillover gain.
6. **Track each field as ready, pending, unavailable or restricted.** Zero/no items/no reputation is displayable only when a complete applicable query establishes it. Otherwise show one compact loading/unavailable notice and keep any independently known fields. A class, race, profession, phase, prerequisite, repeatable/completion or beta-availability constraint cannot be erased by database presence. Passing some eligibility filters does not prove availability.

The explicit-ID and guaranteed/choice paths are visible in [QuestUtils](https://github.com/Gethe/wow-ui-source/blob/943764493e6b16d63ded3ab304150d1f05e58b57/Interface/AddOns/Blizzard_FrameXMLUtil/Mainline/QuestUtils.lua#L765) and [GameTooltip reward item getters](https://github.com/Gethe/wow-ui-source/blob/943764493e6b16d63ded3ab304150d1f05e58b57/Interface/AddOns/Blizzard_GameTooltip/Mainline/GameTooltip.lua#L833). The [world-map reward gate](https://github.com/Gethe/wow-ui-source/blob/943764493e6b16d63ded3ab304150d1f05e58b57/Interface/AddOns/Blizzard_UIPanels_Game/Mainline/WorldMapFrame.lua#L24) demonstrates distinct readiness; [QuestInfo](https://github.com/Gethe/wow-ui-source/blob/943764493e6b16d63ded3ab304150d1f05e58b57/Interface/AddOns/Blizzard_UIPanels_Game/Mainline/QuestInfo.lua#L607) distinguishes offer from log context. Major-faction scope is documented in the [quest-log API](https://github.com/Gethe/wow-ui-source/blob/943764493e6b16d63ded3ab304150d1f05e58b57/Interface/AddOns/Blizzard_APIDocumentationGenerated/QuestLogDocumentation.lua) and [quest-offer API](https://github.com/Gethe/wow-ui-source/blob/943764493e6b16d63ded3ab304150d1f05e58b57/Interface/AddOns/Blizzard_APIDocumentationGenerated/QuestOfferDocumentation.lua).

The optional provider is the ATCF-documented QuestieDB 1.0.5 / contract 3 / Forever revision `e0a6eaa86f181ac99262e34126bcd2ed1a1712d6`. Its [NPC schema](https://github.com/Questie/QuestieDB/blob/e0a6eaa86f181ac99262e34126bcd2ed1a1712d6/src/meta/npcMeta.lua) contains `questStarts`/`questEnds`; its [36-field quest schema](https://github.com/Questie/QuestieDB/blob/e0a6eaa86f181ac99262e34126bcd2ed1a1712d6/src/meta/questMeta.lua) contains starter/finisher and static reputation fields, but **no item-choice or gold reward fields**. It cannot fill those gaps. Its [Forever provenance](https://github.com/Questie/QuestieDB/blob/e0a6eaa86f181ac99262e34126bcd2ed1a1712d6/docs/forever-data.md) records an Era seed and conversion to build 69893, with reviewed changes; that is not a blanket current-build reward/availability guarantee. Read only the public, flavor/contract-checked API. Do not bundle its database, mutate it or evaluate its serialized strings.

## Compact cards, long stacks and native item inspection

Prefer authoritative current interaction offers, then known active/turn-in entries; database-only candidates appear separately under the uncertainty label. Deduplicate cards solely by exact quest ID, never by title: the strongest current evidence controls the card, and lower-priority association provenance remains attached to that same card. Keep evidence classes distinct in state and labels without making duplicate cards for one quest. Use stable source order or localized title/ID order, not a ranking that quietly treats New as better than Existing. One NPC with several quests gets one card per quest, including mixed normal/green/orange variants. No NPC-wide reward total: choices, conditions and different quests make it misleading.

Recommend cards about **300-320 UI units wide**, separated by 4-6 units. A card has a title/status header, a labeled guaranteed-item row and a labeled **Choose one** row when applicable, then a compact money/reputation line. Visual icons are about 18-20 units, inside at least 24-unit hover targets, with native-quality borders/name color and quantity overlays. Quality is not replaced by the quest's green/orange accent. Keep two-line title wrapping readable; a full-title hover can expose a clipped long title without growing every card. A loading notice occupies a reserved slot so returning data does not move an icon under the pointer.

Show about three compact cards initially, with a **scrolling viewport capped at 60% of usable screen height**. Display the full quest count and a visible scrollbar/scroll cue; every known card remains reachable in this stack. Wheel input is handled only inside the stack's viewport and never on the source map/minimap. At a scroll boundary, do not pass the same wheel event through to map zoom. No three-quest data cap and no demand to open the NPC dialogue to inspect the remaining rewards.

Default item groups use one compact row each. When a group has more icons than fit, show an explicit **+N items** or **+N choices** control; activating it expands only that card's affected group inside the existing scroll viewport. All exposed eligible choices remain accessible, separately labeled and individually hoverable. This control expands information only; it never chooses a quest reward or selects/accepts a quest. Keep the clicked card/affordance stable while revealing more rows. Long reputation lists use the same disclosed, per-card expansion rather than increasing every card's height or silently losing factions.

Fit the stack at opening beside the source/native base tooltip, preferring a short pointer journey and free screen space. If the preferred side crosses an edge, place it on the other side, then above/below and clamp its own bounds. Reduce viewport height and scroll, keeping icons and text readable; do not shrink every card to fit the full list. Reserve an outward item-tooltip lane when space permits. Once entered, keep the stack fixed so reward tooltips, async loads or comparison appearances do not relocate cards under the pointer. Anchor only addon-owned frames, using guarded readable measurements and effective UI scales. Preserve native source anchors. Screen size/scale changes may require a controlled re-fit with the hovered exact item retained or a clean dismissal; they must not silently select a different icon.

Each item target retains a readable exact quest ID, reward kind (**reward** or **choice**), exposed index, exact item ID/link, current-player context and session generation. Prefer the native explicit-ID `SetQuestLogItem(type, index, questID)` route for identified remote quests. `SetQuestItem(type, index)` is allowed only while the same current offered quest and NPC session still match; leaving that interaction invalidates the route. An exact captured native item link can use the native hyperlink renderer when it preserves the reward variant/context. A bare generic item ID is not a substitute for a bonus/scaled reward link. If no matching native route is ready, the icon keeps a loading/unavailable indication and does not show stale or fabricated stats.

Render item content through the game's tooltip data/template machinery on an addon-owned item-tooltip frame. Preserve native fonts, quality, collection/equipment information and native comparison rules rather than hand-building item-stat or comparison replicas. Verify the exact native comparison path before enabling it on this owned tooltip. Its item tooltip and any comparisons attributable to that tooltip are part of the interaction area, even if their native frames are mouse-transparent; membership uses guarded visible geometry, not only OnEnter events. Keep the selected item visible while the pointer travels from its icon onto that tooltip. Moving onto another icon switches to that exact item; moving onto blank card space ends item inspection after the same short transit grace while leaving the card stack open.

Ownership isolation is a required feasibility gate, not an assumption from using a Blizzard template. The pinned `GameTooltipTemplate` inherits native hide cleanup; `GameTooltipDataMixin:OnLoad` assigns global shopping tooltips, and native `GameTooltip_OnHide` calls a global battle-pet tooltip hide. The native comparison manager is also shared: cleanup must be identity-scoped to this tooltip, and comparison setup/failure must not issue an unqualified clear against a newer owner's session. Therefore the owned-frame initialization, comparison attachment and cleanup must be verified to affect only this session's frames. Do not borrow, reanchor, clear or hide global `GameTooltip`, `ShoppingTooltip1/2`, `BattlePetTooltip`, another addon's item tooltip, or their newer content. Preserve native scripts on native frames through additive hooks/post-calls. A supported native rendering path with isolated owned-frame cleanup must pass Stage 0 before shipping interactive reward inspection.

The exact item-tooltip arguments are documented in [the pinned tooltip API](https://github.com/Gethe/wow-ui-source/blob/943764493e6b16d63ded3ab304150d1f05e58b57/Interface/AddOns/Blizzard_APIDocumentationGenerated/TooltipInfoDocumentation.lua#L762), with setter mappings in [TooltipDataHandler](https://github.com/Gethe/wow-ui-source/blob/943764493e6b16d63ded3ab304150d1f05e58b57/Interface/AddOns/Blizzard_SharedXMLGame/Tooltip/TooltipDataHandler.lua#L534). [GameTooltip.xml](https://github.com/Gethe/wow-ui-source/blob/943764493e6b16d63ded3ab304150d1f05e58b57/Interface/AddOns/Blizzard_GameTooltip/Mainline/GameTooltip.xml) shows the native item/shopping templates; [native hide and comparison code](https://github.com/Gethe/wow-ui-source/blob/943764493e6b16d63ded3ab304150d1f05e58b57/Interface/AddOns/Blizzard_GameTooltip/Mainline/GameTooltip.lua#L404) establishes the ownership caveat. These prove source contracts, not successful runtime rendering.

## Persistence, dismissal and ownership

Use one session with **Closed, Open and PendingLeave** states. Capture the origin surface, readable NPC/quest identities, exact card order, anchor and generation when the opening gesture succeeds. Sample complete modifier state on entry and both left/right modifier changes. Modifier release does not change Open to Closed. Once open, rendering requires the same captured session/generation and retained interaction, not a currently held modifier or a continuing `mouseover` unit token.

The retained interaction area is the union of: the still-valid source hit area; the stack viewport including card gaps and its scrollbar; and the visible owned item tooltip plus only its verified comparison frames. For a world NPC, a frozen opening cursor point helps define the initial journey, but is not a permanent source hit area. Normal NPC leave or shared base-tooltip hide/clear starts a transit check; it does not destroy the captured cards. Do not use the global base tooltip's current owner as the stack's identity once item inspection begins.

Recommend **250 ms outside-area grace**, plus a narrow, nonblocking geometric corridor between the origin and stack, and between the hovered icon and its item tooltip. The initial origin-to-stack corridor can extend the journey up to **1 second total** only while the pointer is moving toward the destination; reaching the destination ends that special origin corridor. Item-to-tooltip transit uses the same bounded rule. The corridor checks pointer geometry and direction without installing a mouse-catching overlay. Entering any retained region cancels PendingLeave. Remaining outside all retained regions/corridors after the applicable deadline closes the stack. This bounds persistence without requiring unrealistically fast movement across a gap, and must be tuned with actual pointer paths at screen edges/scales. A small inactive frozen origin point cannot keep the stack alive indefinitely.

An icon leave must not immediately hide its item tooltip: retain it while the pointer is crossing toward or over its native item/comparison geometry. Recheck the complete region union after event dispatch so OnLeave-before-OnEnter ordering cannot cause flicker. On blank card space, expire the previous item tooltip after the short grace without closing the stack; on another icon, switch the item and its generation immediately. Scroll/recycle invalidates a hovered offscreen icon and clears only its owned item inspection, never substituting the next pooled card's item.

**Escape closes the stack and its owned item inspection.** Use a uniquely named addon-owned closeable frame with the native Escape/special-frame mechanism, subject to checking its interaction with map/options Escape ordering. Do not install a global keyboard catcher, consume unrelated keys, or change the native map's visibility to achieve this. Escape sets an opening-gesture latch: the same source cannot reopen merely because Shift remains held or native minimap refresh repeats. Re-arm only after the opening modifier has been released and pressed again, or a genuinely fresh valid source entry occurs after dismissal. The None modifier alternative re-arms on a fresh source entry. Whether the same Escape also closes an existing native window must be documented from the exact client check; the addon must not claim priority it has not verified.

Keep the captured stack stable while it is being inspected. A new source encountered during transit is not a silent replacement of its IDs. After leaving/dismissing the old interaction, a fresh qualified source hover can start the next session. Stale replies can populate a bounded safe data cache but cannot reopen a dismissed stack, reorder cards under the pointer or attach an item to a recycled target. Reward callbacks must match quest/reward context, session and target generation.

Distinguish visual source leave from structural invalidation. A source pin release/reacquire, map close/map identity change, zone/world change or feature disable closes immediately. Quest/gossip close invalidates current-offer/session-only reward data and closes a stack tied to that interaction; unrelated gossip closure does not erase a separately identified map/provider stack. Loss of the NPC `mouseover` token while entering addon UI alone is expected and does not close. Restriction or an identity conflict prevents further context-dependent reads and either marks affected fields unavailable or closes that session safely. Never reuse a past NPC offer as proof of present availability. Never hide another addon's tooltip or restore its newer appearance.

Use supported post-calls/events/additive hooks, with secret guards before comparison, indexing, GUID parsing, formatting or cache keys. `pcall` alone is insufficient. Do not alter protected native anchors/visibility, pin click handlers, map filters, selected quest, quest acceptance or completion. Mouse input belongs only to the visible addon cards, icons and scroll controls; their presence never makes the original NPC/marker frame mouse-catching. The [tooltip processor](https://github.com/Gethe/wow-ui-source/blob/943764493e6b16d63ded3ab304150d1f05e58b57/Interface/AddOns/Blizzard_SharedXMLGame/Tooltip/TooltipDataHandler.lua#L181) has additive callback ownership; secure Blizzard code may handle values the addon cannot inspect. Minimap hover already refreshes each frame: skip unchanged source contexts, deduplicate in-flight requests and bound caches, retries and objects. Use a lightweight pointer/geometry monitor only while this stack is open, and unregister it on close; do not add a permanent global ticker. Character-dependent reward/availability observations are session/build scoped and invalidated after relevant quest/player/provider changes, not persisted as universal facts.

## Tests and unresolved product questions

Keep the present exact-ID snapshot unchanged: **880 unchanged, 96 updated and 218 new IDs**, **1,194 IDs / 998 title groups / 18 zones**. Updated means modified/green; New means new/orange; absent means unknown/normal. Classification does not imply an NPC association, a reward change or availability. It is not all-Forever coverage and cannot be expanded by grouping title variants.

Offline tests should cover status mapping, provider absence/wrong flavor/malformed values, association conflicts, fresh/stale interaction ownership, multi-quest/hub mixtures, hidden/ineligible choices, required-money versus reward money, zero versus missing/restricted fields, negative/multiple reputation values, character-context invalidation, cold async replies after dismissal/reuse, both Shift keys and modifier remapping, Shift release while Open, Escape while Shift is held, modifier re-arming, geometric transit deadlines, OnLeave/OnEnter ordering, frozen-source expiry, scroll/recycle cleanup, exact item variants/indices, repeated tooltip refresh without duplicate content/requests, frame/cache bounds, future settings and rename migration. Layout checks span long/localized names, many quests/choices/factions, individual expansion, small screens, fractional scales, optional font fallback, item tooltip edge fitting and native comparison collisions. Retain package/data reproducibility checks.

Approved live acceptance must move the pointer from NPC/pin into first/last cards and onto native item/comparison tooltips, release Shift during inspection, scroll long stacks, expand overflow choices, dismiss with Escape and leave, and verify no reopen/flicker or map zoom leakage. Test cold async data and source/pin teardown during each state; verify the owned native item's cleanup leaves unrelated global item/battle-pet/comparison tooltips intact. Compare every surfaced amount/choice/item tooltip against the native offer for the same character and validate actual tooltip payloads, combat/security/taint and coexistence with XPIsland, ATCF and dialogue/tooltip/quest-map addons. Existing offline QuestTint tests do not establish these new features.

There is no implementation-menu decision for Matt now. Recommended defaults and architecture are above. The genuine unresolved questions are empirical: which ordinary unaccepted Forever quests expose complete reward data, whether native minimap payloads carry reliable identity, how much current NPC association coverage the optional provider has, and whether ordinary faction reputation amounts can be authoritative before acceptance. Stage 0 answers those with bounded probes. A broader independently verified reward dataset or new owned minimap pin system, if required, is a separate scope decision; neither is silently added to this plan.
