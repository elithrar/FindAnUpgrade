# Independent data implementation cross-review

Reviewed the corrected working tree on 2026-10-14 independently of its data
implementation owner. The final production input has 1,250 quests, 1,934 unique
item IDs and 2,266 associations. The P2 duplicate-aggregation guard and P3
generator hardening gap found in the initial cross-review were corrected by the
implementation owner and independently re-reviewed. Both are resolved. No
concrete data implementation blocker remains in the reviewed paths. Neither
original finding claimed a currently shipped malformed row.

This reviewer edited only this report and ignored independent diagnostic probes.
No implementation, checked-in tests, owned data, game installation, merge,
release or publication was changed. Repository `AGENTS.md` and the user-provided
WoW add-on skill's source/validation requirements apply. The complete verifier
was not run while other owners changed the shared branch.

## Initial findings, now resolved

### DC1 — Unresolved restrictions on duplicate occurrences do not reject the quest (P2)

Before correction, at `tools/import_catalog.py:343–371`, `parse` dropped an occurrence with unsupported
class/race restrictions, leaving its item-ID omission records. The main merger
does not add that quest ID to the rejected set. The final exclusion pass at
lines 374–377 removes only the diagnosed quest/item pairs.

Independent reproduction uses the actual importer `main` path, a synthetic
acquisition receipt directory, and the real compiled membership for quest 9:

```lua
q(9, {groups={i(1561)}})
q(9, {classes=ComputeClasses(), groups={i(3578)}})
```

The initial output retained quest 9/item 1561 with no class constraint. Quest 9/item 3578
was diagnosed and excluded. A quest-wide restriction on one occurrence could thus
be lost while a different occurrence survives; pair-level diagnostics cannot
resolve the quest's conflicting or unknown eligibility. The same aggregation
path handles race restrictions.

Require rejection of the entire quest ID when any selected occurrence has an
unresolved explicit class/race restriction, or preserve an explicit independent
resolution before accepting the other occurrence. No affected current-production
quest ID was established; this is an independently reproduced importer guard
defect for a future or changed source snapshot.

### DC2 — A class-token object validates but renders an unrestricted Lua array (P3)

The initial `tools/generate_catalog.py` validated a truthy `classTokens` value by iterating
its entries without requiring a list. Mutating real source quest 96 from
`["SHAMAN"]` to `{"SHAMAN": true}` passed `validate` and `render`.
The emitted value was `classTokens={SHAMAN=true}`; executing the generated bytes
in Lua 5.1 yields array length zero. `SearchModel:Eligibility` therefore skips
the class-list restriction.

Require a nonempty list of supported string tokens. The normal importer emits
lists, and no shipped row has this object shape; the gap concerns the generator's
independent owned-input validation.

## Independent correction re-review

The importer now diagnoses unresolved restrictions on every exact quest
occurrence before requiring reward groups, including helper-only occurrences.
It collects quest-wide rejected IDs before aggregation and diagnoses surviving
pairs on those IDs. The generator now requires nonempty arrays with unique,
validated entries for class, race and prerequisite lists.

`python .work/fresh_data_guard_rereview.py` independently exercises 32 importer
combinations: unknown function and invalid scalar class/race restrictions,
both declaration orders, same-file and separate-file occurrences, and an invalid
occurrence with rewards or no groups at all. Every combination omits quest 9
entirely and diagnoses the previously valid item 1561; reward-bearing invalid
variants also diagnose item 3578. There is no remaining order-dependent union
in those cases.

The same probe independently mutates real quest 96's owned input: object,
empty-list, duplicate-list, scalar and tuple shapes for class, race and
prerequisite arrays. All 15 invalid shapes are rejected. The original
`{"SHAMAN": true}` class mutation therefore cannot render as a Lua hash table.
Receipts are in `.work/fresh-data-guard-rereview-results.json`.

The original `.work/fresh_data_cross_probe.py` was rerun against the fixed tools:
its duplicate fixture now ships no quests/items, all 24 other guard checks pass,
and all four production outputs still reproduce byte-for-byte into ignored
temporary directories. Production coverage and source/Lua bytes are unchanged;
the provenance hash changed because diagnostics were reordered. The independent
lexical/receipt audit was also rerun: all 2,266 associations, 95 source receipts
and nine retained current native receipts pass.
