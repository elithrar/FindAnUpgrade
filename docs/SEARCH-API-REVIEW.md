## Association and constraint checks

The importer never executes upstream Lua. It parses allowlisted literal fields, selects direct authored `q(...,{groups={i(...)}})` associations, and intersects them with a separately pinned compiled Forever membership set. Objective providers, starter items, nested vendors and nested loot are excluded. Every shipped quest/item pair passed the compiled membership check. All 2,311 shipped pairs also independently trace to an immediate authored q-to-i association at their stated source path and line. The compiled side accepts immediate item/source records, explicit positive itemID metadata for typed recipes/mounts/pets, and typed toy item IDs. The pinned [root configuration](https://github.com/ATTWoWAddon/AllTheThings/blob/d75383ccdbff1208b87cf4024fa425c0825a7ad6/.contrib/.db/shared/.config/root.config) defines CreateToy with convertedKey itemID; factory/recipe identifiers are not otherwise treated as item IDs. Missing/expression IDs and nested objectives/vendors failed the independent factory probes. The compiled cross-check carries numeric class/faction constraints; conflicting known constraints are rejected rather than combined into broad compatibility.

Independent parser probes passed for objective/vendor exclusion, unsupported expressions, prerequisite thresholds, unresolved multigiver coordinates and duplicate location conflict handling. Unsupported selected class/race expressions omit the entire record. Unsupported other selected fields are explicitly recorded as omissions and leave eligibility unconfirmed. Unknown preprocessor conditions fail. `sourceQuestNumRequired` retains a validated threshold over exact prerequisite IDs. Source `lvl` means minimum/maximum player level and never supplies the displayed quest difficulty.

An independent scan of all selected authoring inputs found eight enclosing class fields and three faction fields. The class alias was the explicit list of all nine supported classes; narrower direct restrictions are retained. The three Horde parent restrictions are present in the final rows. No selected class wrapper or unresolved narrower parent constraint was found in that scan. The membership file reports no conflicting compiled constraints. Differing locations for quest 96875 retain a conflict flag; the resulting menu suppresses waypoints instead of choosing a supposedly authoritative point.

## Native metadata and reward boundaries

The current [quest contract](https://github.com/Gethe/wow-ui-source/blob/735496de78ebd30ce816a0637982c556987f258c/Interface/AddOns/Blizzard_APIDocumentationGenerated/QuestLogDocumentation.lua) declares exact-ID difficulty reads, quest load requests and their result event. It does not guarantee that a successful request hydrates difficulty for every unloaded quest. The finder accepts readable integer difficulty in 1-200; unavailable difficulty excludes that row from the level band and increments the unavailable count. A cached title without difficulty still gets a deduplicated search-owned request. Missing levels are never converted to source minima or zero. Cold catalogue usefulness is therefore a pending native-client check.

The current [item contract](https://github.com/Gethe/wow-ui-source/blob/735496de78ebd30ce816a0637982c556987f258c/Interface/AddOns/Blizzard_APIDocumentationGenerated/ItemDocumentation.lua) permits missing item info. Full reads are gated on cache readiness; owned requests and matching callbacks recover pending rows. A readable empty equip location is valid cached non-equipment metadata. Specific slot filters exclude it, while All slots permits inspection. Empty equipment checks use the native colon constructor [ItemLocation:CreateFromEquipmentSlot](https://github.com/Gethe/wow-ui-source/blob/735496de78ebd30ce816a0637982c556987f258c/Interface/AddOns/Blizzard_ObjectAPI/Mainline/ItemLocation.lua) with the correct receiver.

Neither generic equippability nor `C_Item.IsUsableItem` proves class-only compatibility. The finder filters known quest class/race constraints, native minimum item level and readable usability from exact validated native reward rows. Unknown item compatibility remains unconfirmed. False native usability is a point-in-time requirement result, not an explanation of class incompatibility. Usability and current native associations reset on reopening and relevant player, equipment, quest, spell and skill events.

Recorded associations carry no fabricated quantities or reward group. Fully ready native guaranteed and choose-one groups replace contradictory catalogue associations and drive subsequent queries. Partial native data retains an explicit recorded fallback. Exact native item links use the addon-owned inspection/comparison machinery with item ID/type checks. There is no numerical upgrade or specialization score; Level fit sorts verified quest difficulty by distance from the player. Major-faction reputation remains explicitly partial, with full known amounts in an owned tooltip and ordinary reputation unavailable.
