# Tooltip layout recovery

## Evidence and cause

All five supplied hover screenshots were inspected from `.work/ui-feedback/image(20261015-111141).png` through `111145`. They show the installed native/Questie tooltip beside a second, much wider preview, and the same quest title, availability and reward amounts repeated in both. The old inspector allocated 320 logical pixels per card regardless of content, a separate availability line, separate 34-pixel icon rows, then money/XP/reputation below those icons. At the photographed client scale this magnified into roughly 530 physical pixels of mostly unused width. Multiple individually bordered cards amplified the height and transparency made the NPC/nameplates compete with text.

The implementation now uses measured text and visible reward content. Inspector cards are 232–280 logical pixels wide, use 24-pixel icons with the native `WhiteIconFrame` rarity border, omit redundant availability rows, place a small single reward group beside its amounts when space permits, and use a less transparent native tooltip background. Fonts retain the native tooltip objects. Guaranteed and choose-one groups remain separate; long content wraps and long stacks scroll. No global font, UI scale, other addon's icon or native tooltip position is changed.

## Settled interaction

- Default: hold the reveal key over a supported source to append compact quest/reward rows to the existing `GameTooltip`. Existing NPC and other-addon content stays intact. A single already-rendered exact quest title and matching amounts are not repeated. Same-title variants retain IDs; amounts from one quest cannot suppress another quest's amounts. The quick preview is bounded to three quest blocks and twelve content rows.
- Release the key to open the persistent interactive inspector. Only QuestBrief's still-owned appended text is cleared first. Native item rendering, rarity borders, comparison controls, pointer transit, scroll and Escape use the existing isolated inspector. Moving toward the inspector can also start the handoff. GameTooltip itself never receives interactive buttons, a new owner, new anchors or mouse interception.
- `Preview layout` selects **Game tooltip** or **Compact inspector**. `Inspection position` selects **Right of cursor** (56 logical pixels before screen/tooltip avoidance) or **Beside game tooltip**. Reveal key **None** opens the inspector directly. Existing saved opt-outs, modifiers, scale and other settings are preserved; the two additive fields are individually validated in schema 3.
- `/questbrief`, `/questbrief search` and `/questbrief s` open search. `/questbrief opts` and `/questbrief options` open settings.

The native quick preview's inline item textures are passive summaries. Native rarity borders and full item/comparison hover are in the interactive inspector. Native classification is a concise orange/green label; tinting an entire NPC tooltip would also tint unrelated content. Inspector cards and quest dialogs retain the classification tint.

## Source contracts and ownership

Target source: Forever 1.60.1.70374, interface 16001, Gethe/wow-ui-source `735496de78ebd30ce816a0637982c556987f258c`. Existing pinned files in `docs/client-contracts.json` cover `DropdownButton.lua`, `SharedTooltipTemplates.lua/xml`, `GameTooltip.xml`, `TooltipDataHandler.lua` and comparison handling. Installed Questie `Modules/Tooltips/TooltipHandler.lua`, `Tooltip.lua` and `MapIconTooltip.lua` establish its additive `AddLine` pattern, exact rendered IDs, marker owner and rebuild lifetime. Installed XPIsland/ATCF options constructors remain the settings reference.

Native augmentation requires a public, visible, unprotected tooltip with the exact current NPC unit GUID or marker owner. Additive clear/hide hooks invalidate owned rows. Owner, primary data object and its identity fields, Questie rebuild token and hover generation guard updates and cleanup. Quest data events re-resolve eligibility and update only unchanged owned text; another addon's edits are preserved. Composition, append and resize paths recheck their session after reentrant callbacks. No original tooltip scripts are replaced. Unsupported identity, restricted data, combat-deferred setup or unavailable native content falls back to the owned inspector.

The complete native supplement occupies **one multiline AddLine row**, reused on metadata updates. Original native/Questie text is never rewritten; this matters because Questie's exact rendered-title checks read those original font strings. Clearing the single owned block cannot leave one intrinsic empty row per reward or quest. On unchanged quest/item metadata events, a visible-content signature prevents relayout and preserves inspected items. Only currently visible item IDs react to item-cache events. The shared `QuestState` owner diffs active/completed quests and current native offers; unrelated log progress causes no hover rebuild. Changes to the current giver's filtered candidates and recorded dependencies can reveal newly unlocked quests while the pointer remains in the inspector.

`GameTooltip:RefreshData()` was investigated in the [matching GameTooltip.lua](https://github.com/Gethe/wow-ui-source/blob/735496de78ebd30ce816a0637982c556987f258c/Interface/AddOns/Blizzard_GameTooltip/Mainline/GameTooltip.lua#L898). It calls `RebuildFromTooltipInfo`, which replays registered data/processor callbacks and clears rendered lines. Manually appended foreign text outside `infoList` is not replayed. Questie's manually constructed map tooltips have no primary tooltip info, and its private `_Rebuild` appends rows rather than clearing them. A blanket rebuild would therefore lose foreign content, do nothing, or duplicate Questie rows. Cleanup instead empties only the still-owned multiline block and invokes the ordinary already-shown tooltip resize path. The native blank-line helpers deliberately use a space rather than empty text; exact empty-block engine geometry still needs client observation.
