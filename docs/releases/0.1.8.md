# FindAnUpgrade 0.1.8

The reward finder now opens as a narrower, taller sidebar with larger reward
icons, verified item levels, yellow quest titles and a settings cog. Text wraps
within the row and guaranteed rewards remain separate from choose-one rewards.
Quest colors control both classification fills and badges.

Same zone is the default filter, within the editable inclusive level range.
Level range widens the scope; Include dungeon quests adds only confidently tagged
quests with an eligible starter and no unresolved chain. Exact quest and NPC
faction checks prevent optional map metadata from bypassing restrictions.

The native sort menu defaults to Biggest upgrade. Class playstyle preferences
estimate stat gain against currently equipped configurations. Missing data,
unverified weapon damage, effects, sets and uncertain equipment legality remain
unranked. Item level is displayed separately and never supplies the score.

One character snapshot owns identity, location, quest and equipment facts.
Event-specific revisions coalesce visible updates, keep empty-slot filtering and
ranking consistent, and defer hidden hydration. QuestState remains the sole
quest-log observer.

The shipped folder and commands are now FindAnUpgrade, `/fau` and
`/findanupgrade`. The development installer preserves and validates old settings,
backs up the verified QuestBrief payload and installs one active folder. Existing
new-name settings are never overwritten; future schema data remains read-only.
Repository renaming and publication remain separate actions.

Source, Lua 5.1, provenance, packaging and independent review records are linked
from `docs/VALIDATION.md`. Native appearance, physical input, actual item API
coverage, combat/taint and client CPU remain live checks.
